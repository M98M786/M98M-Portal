## Findings

### 1. An expired session kept a tab calling the backend once a minute, all night — HIGH · FIXED

The engine transport has always ended an expired session itself (`engineApi`: on `auth` with a live
session it calls `authSelfHeal`). **The sheet transport never did** — it only rejected. So any action
pinned to Apps Script kept a dead session sitting on screen with nothing telling the person why.

My reports is where that surfaced. `paint()` pins `myCheckpoints` to Apps Script for the rest of the
tab (`ENGINE_MISSING`) whenever the engine mirror returns an empty checkpoint list — an 11 Sept
workaround that is still correct. `startTicker()` then polled it every 60 s with an **empty
`.catch(function () {})`** and, alone among the portal's eight pollers, **no `document.hidden`
guard**. A backgrounded My-reports tab whose session had lapsed therefore fired one doomed `auth`
call a minute from **22:08 to 06:07 — eight hours, ~480 wasted Apps Script calls**, against the
slowest tier in the stack.

Three costs, and the third is why it was invisible until tonight:

1. Backend waste — 1,440 failed calls a day per stuck tab, forever.
2. The person's reports rail froze on stale slots and never said the sign-in had expired, so a
   checkpoint could fall due behind a screen that looked fine. `CHECKPOINT_MISSED` fired for
   `m98m786@gmail.com` at 07:05 for the 02:30 slot.
3. **It blinded this audit.** Each `auth` error writes six lines (message + stack) to
   `ACTIVITY_LOG`. At one a minute that is ~8,600 lines a day — `activityTail` scans the last 6,000
   rows, so the real staff lines were being pushed out of the window the audit reads.

**Fixed and live** (`c44e197`, build `20260926-0216`):

- `src/shell.html` — the sheet path now self-heals on `auth` exactly as the engine path does, at all
  three reject sites (single, batched, retried-singly). `authSelfHeal` is capped at once per 10
  minutes, so it cannot become a reload loop.
- `frontend/view-reports.js` — the ticker skips hidden tabs, stops on `auth` and says the sign-in
  expired, and gives up after ten consecutive failures of any other kind.

Verified on `portal.m98mltd.co.uk` by exercising the live function three ways: **no session + `auth`
→ rejects, does not heal** (the login screen cannot loop); **session + `auth` → rejects and heals
once**; **non-auth error → rejects, never heals**. Page parses clean, 97 views register, console
empty. Test state restored.
