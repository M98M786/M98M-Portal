### 3. `scripts/build.py` has exited 1 on every build since 18 September — MEDIUM · FIXED

The ads build ends with a tripwire that asserts the spliced page carries **exactly 13** advertising
views. The `/ads/` front door shipped on 18 Sept with 13; commits `4ad7f10` and `219a0bd` the same
day took it to 15. Since then the script writes every artifact correctly and then dies:

```
ads -> ads/index.html  326212 bytes, modules: 8, advertising views: 15
ERROR: expected 13 advertising views in the ads build, spliced 15 (...)
$ echo $?
1
```

Two things wrong with that. A build that exits non-zero after succeeding will stop any scripted or
CI deploy keyed on the exit code, and will read to a human as "the build failed" — on a night when
it matters, that is a deploy that does not happen. Worse, a guard that fires on every single run
can never warn about anything: the failure it exists to catch, a view silently dropped in the
splice, is now invisible inside the noise it makes.

**Fixed.** The tripwire now counts what the source modules actually declare (`VIEWS.adtool… =`
across `frontend/view-adtool-*.js`) and insists the built page carries every one, instead of
comparing against a number that goes stale the day a page is added. Verified both ways in a
scratch copy: a clean build exits **0**, and a deliberately broken splice (three of eight modules)
still trips it —

```
ERROR: the ads build dropped 10 advertising view(s) the modules declare: adtoolAlerts, ...
```

The committed artifacts were never wrong; only the exit code was. I did **not** re-run the build in
the repo — that would bump `BUILD` and force every open tab in the office to reload for nothing.
